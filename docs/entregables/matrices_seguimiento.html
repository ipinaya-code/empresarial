Incorporar una capa de memoria caché intermedia que procese las consultas masivas de disponibilidad de vuelos, reduciendo la saturación directa sobre el motor principal de la base de datos. Se definió el uso de Redis como capa de caché, junto con políticas de TTL e invalidación por tipo de dato (itinerarios, horarios, tarifas) y la separación entre consultas de lectura y escritura. ○ PENDIENTE DE RESPALDO:
• Código de integración del caché Valkey (cache.py) con políticas de TTL.
• Servicio de disponibilidad optimizado consultando primero en caché.
• Infraestructura Vagrant y Docker Compose incluyendo el servicio Valkey.		 Consistencia entre el caché y el estado real de las reservas es el principal riesgo técnico.
En producción requeriría integración con el motor de pagos, fuera del alcance del prototipo.
Se documenta como limitación del estudio.		 Desplegar Redis en el entorno del prototipo.
Integrar consultas de disponibilidad y ejecutar prueba comparativa.
